## 1. Executive summary

Built a fully-local AI agent that improves its own code inside user-authorized time
windows, scope-locked to `./agent/`, with a pure-Python desktop-style dashboard
(NiceGUI) showing chat, run controls, a live benchmark graph, and an iteration log
with one-click rollback. The only network call is to a local Ollama server; the
agent runs end-to-end without it via a deterministic improver.

**Headline result:** across 6 real, benchmark-gated git commits the agent raised its
own aggregate self-benchmark score **from 54.13 to 80.99 (+26.86, +49.6% relative)**,
with correctness pinned at 100% the entire time.

## 3. Findings

- **Algorithmic rewrites dominate the gains.** The latency benchmark moved 15.73 → 97.91,
  driven mainly by iterative `fib` and 6k±1 primality. The single biggest aggregate jump
  (+11.73) came from replacing the O(n²) duplicate scan with an O(n) set on a 400-element
  near-worst-case input.
- **Quality reached 100** once every public function carried a docstring and the module
  stayed free of bare-`except`/`eval`.
- **An honest tradeoff was surfaced, not hidden.** Token-efficiency *dipped* slightly
  (34.92 → 30.68): docstrings add source bytes, which the token-cost proxy penalises. The
  aggregate still rose strongly, and the system recorded the regression in that one suite
  rather than masking it — exactly the transparency the benchmark design is meant to give.
- **Correctness held at 100% throughout.** The correctness suite is a hard gate; no kept
  change ever broke a test case (29 canonical cases across 5 functions).
- **The loop knows when to stop.** Iteration 7 found no remaining heuristic improvement and
  logged a clean `skipped` — no busywork, no benchmark gaming to manufacture a gain.

## 4. Governance & safety — verified

All six end-to-end tests in `tests/test_loop.py` pass. Each proves a hard constraint:

| Test | Proves |
|---|---|
| improvement climb + clean tree | iterations raise the score and leave the working tree clean |
| revert on broken correctness | a change that fails a test case is hard-reverted |
| anti-gaming meta-check | a benchmark rewritten to `return 100` is rejected (it can't discriminate broken code) |
| kill switch leaves clean tree | killing mid-iteration undoes the candidate commit — zero partial edits |
| locked outside window | the loop refuses to run outside an authorized window |
| scope lock | edits to anything outside `agent/` are blocked before they're written |

**Anti-gaming guard:** any iteration that edits a benchmark *and* raises its own score is
flagged, and edited benchmarks must pass a meta-check (score deliberately-broken code
differently from real code) or the iteration is reverted.

## 5. Architecture

```
core/   loop, git ops, scheduler (authorized windows), db (SQLite),
        benchmarks runner + isolated worker, improver (heuristic + local-LLM), ollama client
ui/     NiceGUI dashboard (app.py) + Plotly charts (charts.py)
agent/  solutions.py (the self-mod target) + 5 versioned benchmarks  ← only writable scope
data/   SQLite database (gitignored)
scripts/ seed.py   tests/ test_loop.py   main.py (single entry point)
run.bat / run.sh + install-desktop-shortcut.* (one-click launchers)
```

Benchmark suites: `correctness` (gate), `latency`, `efficiency`, `quality` — 5 tasks total.

---

## 6. How to run

- **Desktop icon:** double-click `install-desktop-shortcut.bat` once → an
  "AI Improve Agent" icon appears on the Desktop → double-click it any time.
- **Or:** `run.bat` (Windows) / `./run.sh` (macOS/Linux), or `python main.py`.
- App opens at **http://localhost:8080**.
- Chat needs Ollama (`ollama pull qwen2.5-coder`); all other features work without it.
